// Vehiculo.h — Clase abstracta pura
class Vehiculo {
public:
  Vehiculo(const std::string& id,
           const std::string& placa,
           double capacidadKg,
           double velocidadKmh);

  virtual ~Vehiculo() = default;

  // Funciones virtuales puras (interfaz polimórfica)
  virtual double calcularCosto(
    double distanciaKm, double pesoKg) const = 0;
  virtual std::string getTipo() const = 0;
  virtual double calcularTiempoEntrega(
    double distanciaKm) const = 0;

  // Función virtual con default
  virtual bool puedeCargar(double pesoKg) const;

  // Encapsulamiento — getters con const
  [[nodiscard]] double getCapacidadKg() const;
  [[nodiscard]] EstadoVehiculo getEstado() const;

protected:
  std::string    m_id, m_placa;
  double         m_capacidadKg, m_velocidadKmh;
  EstadoVehiculo m_estado {EstadoVehiculo::DISPONIBLE};
};
La clase Vehiculo es abstracta pura: tres métodos virtuales puros que toda subclase debe implementar. Moto, Auto y Camión tienen tarifas diferentes, capacidades distintas y velocidades propias. El compilador garantiza en tiempo de compilación que nadie puede instanciar Vehiculo directamente.

Patrones GoF I — Factory Method & Strategy

🏭 1. Factory Method (Creacional)
Desacopla la creación de vehículos de su uso. El cliente no llama a new Moto() directamente.
// FactoriaVehiculos.h
class VehiculoFactory {
public:
  virtual ~VehiculoFactory() = default;
  virtual std::unique_ptr<Vehiculo>
    crear(const std::string& id,
          const std::string& placa) const = 0;
};

class MotoFactory : public VehiculoFactory {
public:
  std::unique_ptr<Vehiculo>
    crear(const std::string& id,
          const std::string& placa) const override {
    return std::make_unique<Moto>(id, placa);
  }
};
// También: AutoFactory, CamionFactory
💱 2. Strategy (Comportamiento)
Permite cambiar el algoritmo de cálculo de tarifas en tiempo de ejecución según el tipo de paquete.
// EstrategiaTarifa.h
class IEstrategiaTarifa {
public:
  virtual ~IEstrategiaTarifa() = default;
  virtual double calcular(
    double distKm, double pesoKg) const = 0;
};

// TarifaFragilStrategy — precio premium
class TarifaFragilStrategy : public IEstrategiaTarifa {
public:
  double calcular(double distKm,
                  double pesoKg) const override {
    // Tarifa base + 40% por manejo especial
    return (distKm * 2.5 + pesoKg * 0.8) * 1.4;
  }
};
💡 Resultado: La tarifa se calcula automáticamente según tipo de paquete y se muestra en tiempo real en el formulario de registro.
Factory Method permite que el sistema cree vehículos sin saber qué tipo concreto crear. El registro de fábricas actúa como un mapa de constructores por tipo de vehículo. Strategy permite que la tarifa cambie dinámicamente: un paquete frágil paga 40% más que uno estándar, y eso se ve reflejado en tiempo real en la interfaz.

Programación Genérica — Templates Propios & RAII

Cola<T> — FIFO Thread-Safe Genérica
// Cola.h — Template propio
template <typename T>
class Cola {
public:
  void push(T valor) {
    std::lock_guard<std::mutex> lock(m_mutex);
    m_queue.push(std::move(valor));
  }

  [[nodiscard]] std::optional<T> pop() {
    std::lock_guard<std::mutex> lock(m_mutex);
    if (m_queue.empty()) return std::nullopt;
    T val = std::move(m_queue.front());
    m_queue.pop();
    return val;
  }

  // Extracción condicional con lambda predicado
  template <typename Predicate>
  [[nodiscard]] std::optional<T>
    extraerSi(Predicate pred);

private:
  mutable std::mutex m_mutex;
  std::queue<T>      m_queue;
};
Gestión de Memoria RAII
unique_ptr<T> Propietario exclusivo — factorías de vehículos shared_ptr<T> Propiedad compartida — pedidos en flota activa weak_ptr<T> Referencia débil — lista de observadores (evita ciclos)
Templates Adicionales
Repositorio<T, Key>
Almacén asociativo genérico con búsqueda por lambda predicado
Ruta<CoordType>
Cálculo geométrico parametrizado en float o double
✅ 0% punteros crudos con new/delete en la lógica de negocio
Cola T es nuestra estructura de datos central: protege el acceso con lock_guard en cada operación individual. El método extraerSi permite que un repartidor de Moto saque solo los pedidos compatibles con su capacidad, dejando el resto intacto. Repositorio T es nuestro almacén tipo mapa genérico con búsqueda funcional mediante lambdas. Todo el proyecto usa smart pointers —cero new y delete manuales en la lógica de negocio.

Patrones GoF II — Singleton & Observer

🔒 3. Singleton — Scott Meyers C++17 Thread-Safe
ServicioRutas: punto de acceso global único al motor de ruteo vial de Arequipa. Inicializado una sola vez con las 870 rutas OSRM.
// ServicioRutas.h — Singleton (Meyer's)
class ServicioRutas {
public:
  // Instancia única global — thread-safe en C++17
  static ServicioRutas& instancia() {
    static ServicioRutas instancia_;  // init segura
    return instancia_;
  }

  RutaUrbana obtenerRuta(
    const QString& origen,
    const QString& destino) const;

  // No copiable ni movible (garantía Singleton)
  ServicioRutas(const ServicioRutas&) = delete;
  ServicioRutas& operator=(const ServicioRutas&) = delete;

private:
  ServicioRutas() = default;  // ctor privado
  QMap<QString, RutaUrbana> m_cache;
};

// SimuladorEntregas.cpp — hilo por repartidor
void SimuladorEntregas::hiloRepartidor(
    std::shared_ptr<Repartidor> repartidor) {

  while (m_corriendo) {
    std::unique_lock<std::mutex> lock(m_mutex);

    // Esperar hasta que haya pedidos O señal de parada
    m_condVar.wait(lock, [&] {
      return !m_cola->isEmpty() || !m_corriendo;
    });

    if (!m_corriendo) break;

    // Extraer pedido compatible con este vehículo
    auto pedido = m_cola->extraerSi([&](auto& p) {
      return repartidor->puedeAtender(*p);
    });

    lock.unlock();  // liberar antes de entregar

    if (pedido) {
      simularEntrega(repartidor, *pedido);
      // Round-Robin: ceder turno a otros hilos
      std::this_thread::sleep_for(50ms);
    }
  }
}
Primitivas de Sincronización
🔒
std::mutex + lock_guard
Protege la Cola compartida y estadísticas atómicas
📢
condition_variable + notify_all
Despierta a todos los conductores cuando llega un pedido nuevo
⚛️
std::atomic<int>
Contadores de entregados/en-ruta sin lock adicional
🔗
thread::join() fuera del lock
Parada limpia — garantía de deadlock-free
Cada repartidor corre en su propio hilo. Cuando llega un nuevo pedido, el productor hace push en la Cola y llama notify_all para despertar a todos los consumidores. Cada repartidor revisa si puede atender ese pedido según su tipo de vehículo usando el predicado de extraerSi. El sleep de 50ms es el Round-Robin voluntario que evita que un solo hilo monopolice todos los pedidos.

Balanceo de Carga & Prevención de Deadlocks

🔄 Round-Robin Cooperativo (Balanceo de Carga)
Al completar una entrega, el hilo cede el turno 50ms:
std::this_thread::sleep_for(50ms);

Esto permite que el otro conductor del mismo tipo tome el siguiente pedido, distribuyendo la carga de forma equitativa sin un scheduler centralizado costoso.
🚫 Prevención de Deadlocks
  • Regla 1: Siempre se libera el lock antes de llamar a simularEntrega().
  • Regla 2: Los observadores se notifican fuera del mutex de la lista de observers.
  • Regla 3: thread::join() se llama fuera del lock de simulación.
  • Regla 4: Despacho escalonado (700ms) evita accesos simultáneos al mismo tramo de ruta.
